Objective: Implement the Admin Experience Foundation for TravelCore.

Do not redesign backend architecture. Do not change domain ownership. Do
not create new business workflows that are not already represented by
existing contracts. Do not invent operational KPIs or fake business
data.

Required implementation:

1. Admin Shell Refinement

Refine the existing AdminShell from T004 into a professional operational
workspace.

Must support: - responsive admin navigation - topbar -
breadcrumb/context region - content workspace - desktop/tablet/mobile
behavior - dense but readable information hierarchy - long-session
usability - keyboard-friendly interaction patterns where applicable

Do not create a second design system.

2. Professional Data Grid Foundation

Implement a reusable admin data-grid experience pattern suitable for
future TravelCore operational modules.

The grid experience must support, at minimum, the UI/interaction
foundation for: - server-side pagination pattern - column sorting -
type-appropriate column filters - column visibility control - column
reorder pattern if practical within existing stack - row selection -
bulk action pattern - row-level actions - export action surface -
empty/loading/error states - saved-view affordance/pattern -
responsive/mobile behavior - keyboard navigation baseline

Do not invent backend capabilities. If a capability is not backed by an
API yet, implement only the honest UI contract/pattern and clearly label
limitations in evidence.

3. Workflow Patterns

Create or refine representative admin interaction patterns for: - filter
bar - search - form layout - modal/drawer pattern - confirmation
pattern - status/feedback states - stepper/progressive workflow pattern
when appropriate

These are reusable operational patterns, not a new product workflow.

4. Representative Admin Experience

Provide at least one representative admin surface/board that
demonstrates the shell + grid + workflow patterns together.

Use honest existing data/contracts where available.

Do not fabricate operational facts.

information density without visual noise - scanability - fast repetitive
work - clear action hierarchy - long-use comfort - mobile usability -
accessibility - maintainability

generic dashboard template appearance - decorative charts without real
data - fake statistics

read-only fallback.

KPIs as if they are real - use explicit representative/demo-only
